# 構成の設計判断

## 相談内容

### 2026-08-25

**Q:** 会議中に立ち上げておくと議事録が自動生成されるアプリを作りたい。運用コストは完全にゼロにしたい。

**A:** Claude API には音声入力が無いため、構成は必ず3段（①音声取得 → ②文字起こし → ③議事録生成）になる。
無料化の要は③で、選択肢は次の3つだった。

| 案 | 品質 | 実装量 | 備考 |
| --- | --- | --- | --- |
| `claude -p`（Claude Code 定額枠） | Opus 5 そのまま | 小 | レート制限を消費。ネット接続は要 |
| ローカル LLM（Ollama + 4B級） | かなり落ちる | 中〜大 | 完全オフライン。8GB では 4B が上限 |
| 文字起こしまでで止めて手動で貼る | Opus 5 そのまま | 最小 | ひと手間かかる |

**結論:** `claude -p` を採用。マシンに Claude Code CLI がログイン済みで、追加課金ゼロのまま
Opus 5 の品質が得られるため。後から API キー方式へ差し替えられるよう
`lib/server/summarizer.ts` に `Summarizer` インターフェースを切ってある。

---

**Q:** 文字起こしをリアルタイムに回すか、会議後に一括で回すか。

**A:** このマシンは M1 / メモリ 8GB。会議中に推論を回すと Chrome のビデオ会議とメモリ・CPU を奪い合う。

**結論:** 会議後の一括処理。会議中は PCM を書き出すだけで負荷がほぼゼロになる。
副次的に、全体を通して処理できるぶん精度でも有利。

---

**Q:** DB を入れるか。

**結論:** 入れない。会議はせいぜい年数百件で、一覧はディレクトリを読むだけで足りる。
`data/meetings/<id>/` にファイルを並べる形にすると、「保存 = Markdown を書く」で
Markdown 出力の要件も同時に満たせる。

### 2026-08-28

**Q:** 面接の QA まとめのように、自動生成ではない手書きのメモをアプリ上で読めるようにしたい。
議事録の生成物（`minutes.json` / `minutes.md`）に混ぜるべきか。

**A:** 混ぜない。パイプラインが再実行されると上書きされるうえ、`Minutes` 型に
「人が書いた自由記述」の居場所が無い。会議ディレクトリはそもそもファイルを並べる設計なので、
`notes.md` を1本増やすのが素直。

**結論:** `data/meetings/<id>/notes.md` を置くと会議詳細画面に「メモ」として出る。
`files.notesMd` → `readMeetingDetail` → `MeetingDetail.notesMarkdown` と、既存の
`minutes.md` / `transcript.md` と同じ経路で読むだけ。無ければ `null` で節ごと出ない。
議事録の再生成でも消えない。

表示は Markdown ライブラリを足さず、`meeting-view.tsx` の `Markdown` 関数で
見出し・箇条書き・`**強調**` だけを解釈している。手書きメモで使うのはその3つで、
依存を1つ増やすほどではないため。それ以外の記法は素のテキストとして出る。

### 2026-09-08

**Q:** 対面会議だけ議事録にならない。文字起こしが「音楽」の3行だけになる。
録音側を直すべきか、文字起こし側を直すべきか。

**A:** 文字起こし側。録音は正常だった（89秒ぶん、mean -38dBFS。無音ではない）。
whisper が小さい音声の発話を非発話として捨てていた。→ `~/.claude/knowledge/dev_tools.md`

対面だけで起きるのは音源の違いによる。**オンラインはタブ音声というフルスケールの
デジタル信号が混ざるので実測 -22dBFS 前後に収まる**が、対面はマイク1本で部屋の空気を
拾うだけなので -38dBFS まで落ちる。マイクの設定（`echoCancellation` を切る等）は
対面向けに正しく分岐できていて、そこは原因ではなかった。

**結論:** `pcmToWav`（`lib/server/wav.ts`）で、WAV 化と同時に音量を揃える。
入れ場所をここにしたのは、パイプラインで音声が必ず1回通る唯一の地点で、
再実行（`status: error` からの「同じ音声で再実行」）でも同じ処理が効くため。

- **一律のゲインではなく、500ms のフレームごとの動的正規化**にした。
  一律だと区間ごとの比率が変わらず、静かな区間は静かなまま残って直らない（実測で確認）。
- **`audio.pcm` は書き換えない。** 正規化するのは `audio.wav` だけ。
  マイクが実際に拾えていたレベルを後から `preview.sh` で確認できる状態を残したいため。
- ffmpeg の `dynaudnorm` に投げれば1行で済むが、**ffmpeg を必須依存にしたくなかった**。
  現状 ffmpeg を使うのは `preview.sh` だけで、README の「必要なもの」にも入っていない。
  自前の実装は 60 行ほど、1時間の音声で 2.2 秒（文字起こし 8 分に対して誤差）。
- 元から十分な音量の音声に掛けても悪化しないことは、既存のオンライン会議の録音で確認した
  （別の `DATA_DIR` に複製して回帰確認。むしろ取りこぼしが減った）。

---

**Q:** 何も録れていない会議と、録れているが小さすぎる会議を、どう区別させるか。

**結論:** `pcmToWav` が実測した音量（`rmsDbfs`）を返し、発話が1つも取れなかったときの
エラーメッセージに載せる。`音声から発話を検出できませんでした（録音レベル -68.2dBFS）` のように出る。
-60dBFS を下回っていればマイクが拾えていない、それ以上なら距離や環境の問題、と切り分けられる。

## 詰まったところ

### 2026-09-08

- **状況:** 対面会議の議事録に会話内容が入らない。
- **原因:** whisper が発話を非発話（`音楽`）と判定して全部捨てていた。録音そのものは正常。
- **解決策:** `pcmToWav` で動的正規化を入れた（→ 相談内容 2026-09-08）。
- **もう1つの穴:** 非発話注記の除外が `/^\[.*\]$/` だけだったため、括弧なしで来た `音楽` が
  素通りして議事録生成まで流れていた。結果、**何も録れていない会議から
  それらしい議事録ができてしまい失敗に気づけない**状態だった。
  `lib/server/transcribe.ts` の `NON_SPEECH` で括弧なしの定型文も落とすようにした。

### 2026-08-28

- **状況:** `notes.md` 対応を実装し、`http://localhost:3000` を見ても「メモ」が出てこなかった。
- **原因:** `scripts/launcher.sh` は `pnpm start`（＝ビルド済みの `.next` を配信）で起動するので、
  `next dev` と違ってソースを変えても反映されない。
- **解決策:** `pnpm build` → `scripts/stop.sh` → `pnpm start -p 3000` で入れ直す。
  アプリの挙動を変えたときは毎回これが要る（`scripts/launcher.sh` 自体の変更だけなら不要）。

### 2026-08-25

- **状況:** `claude -p` にユーザープロンプト側でスキーマを指定して JSON を返させようとした。
- **問題:** スキーマを完全に無視され、`meeting` / `agenda_items` / `action_items` など独自のキー構成で返ってきた。
- **原因:** CLI 経由には structured outputs のような保証が無く、ユーザープロンプト内のスキーマは
  単なる要望として扱われる。
- **解決策:** スキーマを `--system-prompt` 側に移し、「スキーマに無いキーを追加してはいけない」と明示した。
  これで安定した。加えてパース失敗時に1回だけ再試行し、それでも駄目なら生テキストを
  `minutes.md` に残すフォールバックを入れてある（議事録を失うより良い）。

- **状況:** `next build` で `Static analysis determined that this filesystem access causes the whole project to be traced` という警告。
- **原因:** `lib/server/config.ts` の `path.join(process.cwd(), p)` が動的なため、
  Turbopack がプロジェクト全体を出力に含めようとしていた。
- **解決策:** ローカル専用でトレースは不要なので `path.join(/* turbopackIgnore: true */ process.cwd(), p)` を付けた。
